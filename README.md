# DianBiao · 12 路电表脉冲采集

后续项目复用入口：[智能硬件通用开发指南](docs/智能硬件通用开发指南.md)，包含 MQTT、Wi-Fi/BLE 配网、OTA、热点 Web 与布局风格、设备管理 API、三端分类兼容、开发顺序及验收模板。

ESP32-S3 N16R8（16 MB Flash、8 MB OPI PSRAM），固件版本 `v1.0.10`。

v1.0.10 将 MQTT 心跳精简为设备状态，不再携带 `meters`；12 路电量继续通过 `meter_energy` 按配置周期单独上报，`report_now` 仍分别发送心跳和电量两条报文。Topic 中 `{MAC}` 展开为带冒号的大写 MAC，裸 `MAC` 展开为无冒号的大写 MAC，支持混用和重复。已有 Topic 模板保留，升级后按新规则展开；默认 `dianbiao/meter/{MAC}` 会变为带冒号 Topic，上位机需同步订阅/发布。需要无冒号可配置 `dianbiao/meter/MAC`。见 [v1.0.10 验证记录](docs/验证记录-v1.0.10.md)。

v1.0.9 参考 Yanzhenji2.0 补齐移动 APP 接入协议：热点/局域网新增 `GET /api/device-info`，与 BLE a04 共用公共设备信息并返回 `wifi_port`、`wifi_status`；BLE 凭证支持普通写入与无响应写入，保留密码中的空格。联网后在后台向同一平台登记，成功每 60 秒刷新、失败每 15 秒重试。电表广播仍为 `DianBiao_<12位MAC>`，默认热点仍为 `DianBiao_<6位MAC>`；APP 的“设备类型管理”须已有标识为 `DianBiao_` 的电表类型才能显示扫描结果。APP 源码未修改。接口、验证范围和升级步骤见 [v1.0.9 验证记录](docs/验证记录-v1.0.9.md)。

v1.0.8 修复总电量在网页与 MQTT 中末位不一致的问题。此前网页使用 JavaScript `toFixed(3)`，MQTT/BLE 使用 ESP32 `String(double, 3)`，两条格式化路径在舍入边界可能相差 0.001kWh。现统一在设备端四舍五入到三位小数并输出同一数值文本，网页、MQTT、BLE 共用；不修改脉冲数、初始电量或内部计量精度。初始 85858、常数 1600、4 个脉冲统一输出 `85858.003`。见 [v1.0.8 验证记录](docs/验证记录-v1.0.8.md)。

v1.0.7 删除当前功率显示、状态字段及脉冲速率估算。实时总览新增固定 3 行 4 列的总用电量表格，每格上方为通道名称，下方为总电量（含初始电量，单位 kWh）；脉冲与常数详情可展开查看。MQTT 心跳包含设备信息及全部 12 路总电量，周期电量上报同样仅保留每路 `ch`、`name`、`energy_kwh`。配置回执仍通过 `get_config` 或保存配置触发。见 [v1.0.7 验证记录与报文说明](docs/验证记录-v1.0.7.md)。

v1.0.6 将全部 12 路的默认脉冲常数及无效零值的回退值统一为 `1600 imp/kWh`。已保存的非零通道配置继续保留；旧设备如需全部改为 1600，应在采集配置页逐路填写并保存。现场空载自增及短接无响应的问题，用户已确认由供电异常引起，恢复供电后解决。

v1.0.5 增加通过校验的脉冲诊断日志，包含通道、GPIO、增量、累计值及最近一次高/低电平时长，每路最多每秒输出一次，不在 ISR 内打印。修复 MQTT 缓冲常量被库默认值覆盖导致大报文无法发布的问题，并严格解析 JSON 命令，忽略同 Topic 回显的心跳/电量/配置。保留 v1.0.4 的过滤阈值，用于定位仍然出现的实板空载误计数。见 [v1.0.5 验证记录](docs/验证记录-v1.0.5.md)。

v1.0.4 针对空载偶发误计数增加完整脉冲校验：高/低电平各至少 1ms，完成高电平后在下降沿计数，有效上升沿仍至少间隔 10ms；忽略上电及清零时已经存在的高电平，输入使用弱下拉。保留 IRAM 采集与原有持久化格式。此版本过滤短毛刺，不代表已定位或修复现场干扰来源；实际电表最短高/低脉宽必须满足阈值。见 [v1.0.4 验证记录](docs/验证记录-v1.0.4.md)。

v1.0.3 修复脉冲采集在 Flash 写入期间的中断配置：启用 Arduino IRAM 中断分发与计时函数，ISR 使用的数据显式放入内部 RAM；12 路回调均传入非空通道上下文。累计脉冲与电量读取包含尚未收集的中断增量，Web/MQTT/OTA 重启前保存等待和升级期间新增的计数。GPIO 映射、10ms 最小脉冲间隔及 NVS 格式保留。验证与实板验收步骤见 [v1.0.3 验证记录](docs/验证记录-v1.0.3.md)。

底板网表与引脚、电平及共地限制见 [底板引脚核对](docs/底板引脚核对.md)。可运行 `python scripts/check_meter_netlist.py` 重复核对 12 路硬件到固件的通道映射。

Web 门户沿用 QC_ESP32 的深色背景、薄荷绿强调色、圆角卡片、顶部标签导航和表单样式。全部页面资源随应用固件提供，设备热点模式下无需访问外网。

| 页面 | 内容 |
|---|---|
| `/#overview` | Wi-Fi、MQTT、时间、运行时长、3 行 4 列总电量表格及可展开的通道详情 |
| `/#config` | 12 路独立配置卡片：使能、名称、初始电量、脉冲常数、累计脉冲与清零 |
| `/#wifi` | 按需扫描、手动连接、隐藏网络连接 |
| `/#mqtt` | MQTT、上报周期、设备名称、NTP、静态 IP、设备热点配置 |
| `/#ota` | 固件 URL、MD5、大小及 MQTT 升级示例 |

总电量表格在手机与桌面均保持 3 行 4 列，通道名称在上、电量在下。手机的详情卡片和表单使用单列，导航栏可横向滑动；桌面详情四列、通道配置三列，普通表单双列。密码默认隐藏，可勾选显示。长名称与代码内容在区域内换行。

v1.0.2 将代码架构改为 QC_ESP32 的静态单页和 JSON 接口：HTML/CSS/JS 在构建时嵌入 Flash，通过 Arduino `WebServer.send_P` 发送；标签在浏览器本地切换，配置只在需要时读取，轮询仅更新变化的数值，保留编辑内容和焦点。总览约每秒更新，其他标签约每 5 秒更新，请求完成后再计时；后台页面暂停轮询，接口请求有超时和防重入保护。

HTTP、DNS、配置提交和配网状态机由主循环处理。Web/BLE 配网共用队列，先响应后切换无线连接；仅点击扫描按钮时异步扫描。MQTT 握手交给独立任务，握手期间其他代码不访问同一 MQTT 客户端，并修复失败后的 10 秒重试计时。BLE 状态通知按时间重发，取消连续等待。计数落盘合并为一次 NVS 会话，仅写变化的通道。

GPIO 映射、计量公式、MQTT 报文/Topic 展开规则、NVS 命名空间与键名、分区表及 BLE UUID 保留。表计配置即时生效，MQTT/系统配置保存后重启。旧页面地址 `/config`、`/mqtt`、`/wifi`、`/ota_web` 仍会打开对应标签。

## 构建与打包

在 Windows PowerShell 7 中执行：

```powershell
$pio = "$env:USERPROFILE/.platformio/penv/Scripts/platformio.exe"
& $pio run -e esp32-s3-devkitc-1
pwsh -NoProfile -File scripts/package_firmware.ps1
```

本项目的 `esp32-s3-devkitc-1` 环境已配置为 N16R8 的 16 MB Flash 与 OPI PSRAM。打包仅生成 16 MB OTA 应用和首次串口烧录合并镜像，见 [dist](dist/README.md)。网页嵌在应用中，无需上传文件系统。

默认热点为 `DianBiao_XXXXXX`，密码使用设备现有配置；默认未设热点密码。热点访问地址为 `http://192.168.4.1/`，也可通过设备 STA 地址访问。
