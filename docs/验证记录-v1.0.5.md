# v1.0.5 · 空载计数诊断与 MQTT 报文修复

## 日志能说明什么

用户提供的 v1.0.4 日志中，51.577秒和55.777秒分别清零第8、9路；这些保存记录不能直接证明有输入脉冲。85.865秒的周期保存说明之后有新增待保存计数，但日志没有通道和时长信息，也不表示脉冲恰好在85.865秒发生。

MQTT 命令处理及 Web 非 HTTP 拒绝路径没有增加脉冲数的代码。计数增量来自 GPIO 中断通过低电平至少1ms、高电平至少1ms、有效上升沿间隔至少10ms的校验。可能存在符合这个时序的干扰，但没有实测波形时不能把物理根因归结为供电、某个元件或 MQTT 活动。本版保留过滤规则，补充可核对的诊断信息。

## 脉冲诊断日志

示例，非实测：

```text
[PULSE] CH=3 GPIO=5 accepted=1 total=1 high_us=2400 low_us=1200000 at_us=3100000 level=0
```

- `CH` 是1起始的通道/CN编号；`GPIO` 是实际采集引脚。
- `accepted` 是距上一条该通道诊断日志新增的有效脉冲数，`total` 是当前累计数。
- `high_us`、`low_us` 是最近一次通过校验的脉冲高电平及其前导低电平时长，单位微秒。批量增量的时长只描述最后一次，不能代表批次中每个脉冲。
- `at_us` 为该脉冲上升沿的微秒时间戳，约71.6分钟回绕；`level` 是打印时的 GPIO 电平，不是采集时的电平。
- 时长由中断采样得到，受中断延迟及未捕获边沿影响，不能替代示波器测量。

ISR 只更新内部 RAM 状态。主循环读取快照、聚合并限速打印，每路最多每秒一条；无新增计数不打印，清零取消该路待输出的旧摘要。

## MQTT 修复

`mqtt_handler.h` 原先在包含 `PubSubClient.h` 后，用 `#ifndef MQTT_MAX_PACKET_SIZE` 定义4096。然而库头文件已经定义默认256，因此应用宏没有生效，`setBufferSize(MQTT_MAX_PACKET_SIZE)` 实际仍设置256。12路电量和配置报文超过此容量，符合用户日志中1519/1138字节发布失败的现象。此前 MQTT 替身没有模拟容量限制，未覆盖此问题。

现在使用独立的 `MQTT_BUFFER_BYTES=4096` 显式分配，检查返回值和实际容量；发布时按报文加 Topic/协议头所需长度检查，必要时扩容，失败保留错误日志并在后续发布重试。启动日志包含 `[MQTT] buffer=4096 bytes`。

默认发布和订阅 Topic 相同，导致自身心跳被回送并打印为 `cmd`。本版保留已配置 Topic，但使用 ArduinoJson 精确识别 `cmd` 或 `msg_type` 中的 `ota/upgrade/report_now/get_config/reboot`；心跳、电量、配置和未知命令忽略，名称或 URL 中含 `reboot` 不会执行重启。之前仅靠任意子串匹配的非标准消息不再当作命令。

已通过的主机测试：

- 原有12路 GPIO/CHANGE/下拉配置、1～100Hz有效脉冲、200Hz间隔过滤、空载120秒、1/100/999μs毛刺、1ms高低电平边界、上电/清零已有高电平、微秒回绕、保存及失败重试。
- 诊断日志包含通道、数量、累计值和时长；中断内不打印，主循环按通道聚合、限速。

- 同 Topic 心跳/遥测回显不执行命令、不触发重启；明确命令正常处理，包含 `reboot` 的升级 URL 不会误触发重启；原有 MQTT 握手任务、超时重试与客户端所有权回归通过。

固件构建、最终 ELF/IRAM 检查和打包通过。静态 RAM 为55,692字节，Flash应用代码/数据为1,083,805字节。交付文件的大小、MD5/SHA256、OTA与构建产物一致、首次烧录镜像的应用偏移以及与v1.0.4分区一致性均已复核，见 [manifest.json](../dist/manifest.json)。

## 实板下一步

后续收到的日志已发现 GPIO10/GPIO11 多组互补时长和相差1～2µs的反向边沿，应优先排查 U15 相邻输出/输入之间的异常连接，具体证据和断电测量步骤见 [空载异常定位](空载异常定位.md)。此假设仍需实测验证。

升级后确认页面版本为v1.0.5，启动日志缓冲容量为4096；当前所有端子空接时清零，再保留出现增长前后的 `[PULSE] CH=...` 日志。先据此确定是哪个 GPIO、观察到怎样的高低电平时长，再检查对应硬件。

若仍是 GPIO5/GPIO6：分别核对 U14 的3/5脚输入预期3.3V、4/6脚输出预期0V，并检查 R8/R11 上拉、R9/R12、U4/U5 和 H1 焊接接触。万用表只适合初步排查电源和静态电平；需要示波器捕获输入/输出毛刺以定位。底板供电、无线收发和 Flash 操作是否与干扰相关，需要对照实测，不能从 MQTT 错误时间直接推断。

本版未在实板烧录验证，不能宣称空载误计数已经解决。计数过滤阈值、GPIO、NVS格式和分区保持兼容；重启/断电窗口及30秒保存周期的限制保留。
