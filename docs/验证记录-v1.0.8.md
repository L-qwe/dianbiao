# v1.0.8：总电量舍入一致性

## 复现与原因

初始电量 85858kWh、脉冲常数 1600imp/kWh、累计 4 脉冲，数学结果为：

`85858 + 4 / 1600 = 85858.0025 kWh`

按三位小数四舍五入应显示 85858.003。

旧网页接收 ArduinoJson 序列化的浮点数，再调用 JavaScript `toFixed(3)`；旧 MQTT/BLE 则调用 ESP32 `String(double, 3)`。本地已核对所用 ESP32 Arduino 框架的 `WString.cpp` 和 `stdlib_noniso.c`：后者使用 `dtostrf()`，先加舍入量，再缩放并逐位抽取十进制数字。该算法在本例可复现输出 85858.002，而浏览器为 85858.003。差异来自格式化路径，不需要通过少一个脉冲才能复现。

## 修复

- 新增共用 `format_energy_kwh()`，先在设备端按 0.001kWh 四舍五入，再按整数部分和三位小数生成数值文本，正常电量范围不再使用 `String(double, 3)`。
- Web 状态接口通过 ArduinoJson 的 `serialized()` 输出这段数值文本，保持 `energy_kwh` 为 JSON 数字；MQTT 心跳、周期电量和 BLE 运行信息使用同一函数。
- 不提前舍入初始电量或每次脉冲增量，不回写已舍入的总电量；内部仍按初始电量和完整累计脉冲计算，NVS 数据格式保持兼容。
- 极大数值避免整数转换溢出；非有限或负的异常电量输出 JSON `null`。

同一时刻、同一累计脉冲数的输出一致；网页轮询和 MQTT 定时发布仍有各自时刻，持续输入脉冲时应比较相同采样状态。
