# v1.0.10：心跳精简与 Topic MAC 格式

## 行为调整

- `msg_type=heartbeat` 只上报设备状态，删除 `meters`，保留在线标记、MAC、名称、版本、IP、RSSI、时间、NTP 状态、运行秒数、空闲堆和电量上报间隔。
- `msg_type=meter_energy` 继续上报全部 12 路 `ch`、`name`、`energy_kwh`，保留停用通道和原电量舍入。周期由 `rep_s` 控制，0 为关闭。
- `report_now` 仍分别发送心跳、电量两条报文，心跳不夹带电量。配置回执 `meter_config` 保留。
- 心跳不再读取/格式化通道电量，预留字符串容量由 1600 降为 512 字节，不限制实际字符串增长。
- Topic 中 `{MAC}` 展开为带冒号大写 MAC，裸 `MAC` 展开为无冒号大写 MAC；先处理花括号形式，支持混用和重复，不替换小写 `mac`。

以 `84:C7:BB:70:63:38` 为例：

| 模板 | 实际 Topic |
|---|---|
| `dianbiao/meter/{MAC}` | `dianbiao/meter/84:C7:BB:70:63:38` |
| `dianbiao/meter/MAC` | `dianbiao/meter/84C7BB706338` |
| `meter/{MAC}/MAC` | `meter/84:C7:BB:70:63:38/84C7BB706338` |

规则仅用于 MQTT 发布/订阅 Topic。Client ID、BLE 名称和在线标记生成方式保留；空 Topic 仍回退为前缀加无冒号 MAC。

## 升级兼容

已有 NVS Topic 模板不会改写。含 `{MAC}` 的实际 Topic 从 v1.0.10 起会包含冒号；升级前后上位机订阅和下发 Topic 要同步。需要原无冒号格式时，在网页把对应模板设为 `dianbiao/meter/MAC`。

心跳消费者不能继续从心跳读取电量，应按 `msg_type=meter_energy` 处理。计量、NVS、设备管理 API、分区和 GPIO 保留。
