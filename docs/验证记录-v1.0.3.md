# v1.0.3 · 脉冲采集中断修复

## 修复内容

- PlatformIO 启用 `CONFIG_ARDUINO_ISR_IRAM=1`。Arduino GPIO 服务使用 `ESP_INTR_FLAG_IRAM` 注册，GPIO 分发函数及 `micros()` 一起编译到 IRAM，避免只给业务回调加 `IRAM_ATTR` 而底层仍在 Flash 的问题。
- ISR 的计数、时间戳和通道上下文显式使用 `DRAM_ATTR`，不依赖外部 PSRAM/Flash。每路传入独立的非空上下文，避免 CN1 的零通道号被 Arduino 2.x 当作无参数回调。
- 累计脉冲与电量读取包含中断暂存增量，无需等下一次主循环收集。
- Web 延迟重启、MQTT 重启以及 OTA 成功后的重启，在等待结束后保存计数，包含等待/升级过程中新增的脉冲。
- GPIO 映射、上升沿触发、10ms 最小间隔、1600 imp/kWh 默认常数及 NVS 格式保持兼容。

## 自动验证

在 Windows PowerShell 7 中执行：

```powershell
python scripts/test_meter_persistence.py
python scripts/test_mqtt_worker.py
python scripts/test_portal.py
python scripts/test_http_transport.py
$pio = "$env:USERPROFILE/.platformio/penv/Scripts/platformio.exe"
& $pio run -e esp32-s3-devkitc-1 -j 4
python scripts/check_pulse_iram.py
pwsh -NoProfile -File scripts/package_firmware.ps1
```

主机测试直接编译生产计量代码，外围 GPIO、时间和 NVS 使用替身，覆盖：

- CN1～CN12 引脚、输入模式、上升沿中断和非空回调参数。
- 全部 12 路在 1/10/50/100Hz 下每路输入 100 个脉冲，均累计 100；200Hz 输入被 10ms 间隔过滤为 50，验证现有频率限制。
- 9ms 过滤、10ms 接受、微秒时间戳回绕，以及读取尚未收集的计数与电量。
- 保存期间 12 路各新增 10 个脉冲，后续收集/保存不丢失。
- 原有首次初始化、重启恢复、单路清零隔离、NVS 写入/打开失败重试。
- 实际 MQTT 重启指令在 300ms 等待结束后保存计数，再调用重启；原有 MQTT 连接任务、设置校验和 HTTP 预解析测试。

`check_pulse_iram.py` 检查最终 ELF 中业务 ISR、Arduino GPIO 分发、`micros()`、ESP-IDF 计时与 GPIO 中断服务位于 IRAM，四组中断数据位于内部 DRAM。此检查验证编译产物的存放位置，不模拟实板关闭 Flash Cache。

上述四项主机测试、固件构建、最终 ELF 检查与打包均通过。构建静态 RAM 为 55,200 字节，Flash 应用代码/数据为 1,081,361 字节。OTA 文件与构建产物一致，首次烧录镜像的应用位于 `0x10000`，分区表区域与 v1.0.2 一致；交付文件大小和 MD5/SHA256 已复核，见 [manifest.json](../dist/manifest.json)。

## 实板验收与限制

尚未烧录或测量真实 DDS606 电表。电表铭牌的 50Hz 是交流电网频率，不能据此推定脉冲频率；1600 imp/kWh 表示每个脉冲对应 0.000625kWh。10ms 过滤的理论上限为 100Hz，对应 225kW，实际应预留余量。

1. 核对 CN1～CN12 走线与代码一致，确认 74HC14 到 GPIO 的输出为 3.3V 电平；核对电表脉冲输出类型、极性、光耦输入电流及上拉电路。
2. 使用匹配隔离输入电路的脉冲源，逐路在 1/10/50Hz 下送入已知数量脉冲，确认累计值和通道对应关系。50Hz 连续 60 秒应增加 3000 个脉冲，覆盖周期性 NVS 保存。
3. 连续输入期间保存配置并执行 OTA 下载，确认累计数持续增加；停止输入后重启，检查累计值恢复。单独测量重启窗口，并排除该窗口后再做脉冲数对账。

CPU 重启、启动初始化和断电期间无法通过软件中断采集；突然掉电仍可能损失最近 30 秒尚未保存的计数。NVS 写入失败时保留 RAM 待重试，但不能保证故障后的掉电保存。需要跨重启/断电零丢失时，必须额外设计持续供电或独立硬件计数。

依据：[Arduino 2.0.17 IRAM 开关](https://github.com/espressif/arduino-esp32/blob/2.0.17/cores/esp32/esp32-hal.h)、[ESP-IDF IRAM 中断要求](https://docs.espressif.com/projects/esp-idf/en/v4.4.7/esp32s3/api-reference/system/intr_alloc.html#iram-safe-interrupt-handlers)。
